# Contributing

Thank you for your interest in the Open Accessible Smartwatch.

This is an early-stage project. At the moment, contributions that help us clarify the concept, build the community, validate assumptions, and prepare a credible prototype are especially valuable.

## Ways to help

We welcome contributions in areas such as:

- community and outreach,
- English writing and editing,
- social media,
- public relations,
- video and visual communication,
- accessibility,
- neurodivergent user experience,
- open-source project organization,
- embedded systems,
- low-power electronics,
- sensors,
- mesh networking,
- security architecture,
- industrial design,
- manufacturing,
- hardware crowdfunding and Crowd Supply preparation.

## Start with an Issue

Please look at the open Issues first.

If you see something you can help with, leave a comment describing:

- what you would like to contribute,
- relevant experience if applicable,
- roughly how much time you would like to offer,
- whether you prefer a small one-off task or an ongoing role.

You do not need professional credentials to contribute to community, writing, testing, accessibility feedback, or documentation.

## Volunteer contributions

At this stage, many contributions are voluntary.

We want this to be transparent and respectful:

- volunteering is optional,
- contributors should choose clearly bounded tasks,
- no one should feel pressured to provide unpaid professional labor,
- authorship and meaningful contributions should be credited,
- if the project later becomes commercially funded, contributor roles and paid work should be reassessed rather than assumed to remain unpaid.

## Neurodivergent participation

Neurodivergent contributors are especially welcome.

Please communicate access needs or preferred working styles when useful. Examples may include asynchronous communication, written instructions, clearly scoped tasks, extra processing time, or reduced meeting load.

No disclosure of diagnosis is required.

## Safety and claims

Please distinguish clearly between:

- implemented features,
- prototype features,
- planned features,
- research goals.

Do not describe unvalidated emergency, medical, battery-life, security, positioning, or solar-power features as proven capabilities.

## Code and hardware contributions

Before submitting substantial code, firmware, schematics, PCB work, or other intellectual property, please open an Issue first.

The project is still selecting its final licensing model, so we want licensing expectations to be clear before accepting substantial technical contributions.

## Communication

Please keep discussion constructive, specific, and focused on improving the project.
